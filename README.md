# ארכיון WIZ: אתר מקומי עם חיפוש

## הפעלה ראשונה

הפרויקט נמצא ב-`~/repos/wiz-archive` ועובד גם ב-Mac וגם ב-Linux (Debian / Ubuntu / Mint).

1. מעתיקים את כל קובצי `wiz-001.pdf` עד `wiz-126.pdf` לתיקייה `pdfs`.
2. מריצים בטרמינל מתוך התיקייה: `./run.sh`
   - **Mac**: אפשר גם לגרור ל-Terminal את `run.command` או ללחוץ עליו לחיצה כפולה
     (אם macOS חוסם אותו: לחיצה ימנית ← Open). בפעם הראשונה הסקריפט מתקין את Homebrew,
     Tesseract (כולל עברית) ו-Poppler. ההתקנה לוקחת כמה דקות ועשויה לבקש את סיסמת המחשב.
   - **Linux**: הסקריפט לא מתקין חבילות בעצמו. אם חסר משהו, הוא מדפיס את שורת ההתקנה
     המדויקת. ההתקנה המלאה, פעם אחת:

         sudo apt install tesseract-ocr tesseract-ocr-heb tesseract-ocr-eng poppler-utils python3-venv

     (לפרסום, `deploy.sh`, צריך Node.js 22 ומעלה. אם הגרסה במחשב ישנה יותר או חסרה,
     הסקריפט מוריד Node.js רשמי לתיקייה `.tools` בלי לגעת במערכת.)
3. אחר כך רץ ה-OCR. על 126 גליונות (כ-6,500 עמודים) זה ייקח בערך 30 עד 60 דקות,
   תלוי במחשב. אפשר לעצור באמצע (Ctrl+C) ולהריץ שוב. עמודים שכבר עובדו לא יעובדו מחדש.
4. בסוף האתר נפתח בדפדפן. בפעמים הבאות פשוט פותחים את `site/index.html`.
   לא צריך שרת ולא צריך אינטרנט.

## מה יש באתר

- **גליונות**: כל הכריכות, מסודרות לפי שנים.
- **דף גליון**: תוכן העניינים עם קישורים ישירים לעמודים, ותמונות מוקטנות של כל העמודים.
- **קורא**: עמוד בודד או כפול. מדפדפים בחיצים ←/→, לחיצה על העמוד (או המקש Z) מגדילה אותו,
  וההגדלה נשמרת במעבר בין עמודים. Esc חוזר לדף הגליון. במחשב, קיצורי המקלדת מוצגים מתחת לעמוד.
  בטלפון: מחליקים ימינה/שמאלה כדי לדפדף, וכדי להגדיל את העמוד צובטים, מקישים פעמיים או לוחצים על 🔍.
  כשהעמוד מוגדל, גוררים באצבע אחת כדי לזוז בו לכל הכיוונים.
  הכפתור ☰ בסרגל התחתון פותח את תוכן העניינים של הגליון.
  מילות החיפוש מסומנות בצהוב על גבי הסריקה, ובפאנל הצד מופיע הטקסט שזוהה.
- **חיפוש**: בכל הטקסט של כל הגליונות. חיפוש של כמה מילים מחזיר עמודים שבהם מופיעות כולן,
  ו-"ביטוי מדויק" נכתב במירכאות. אפשר לסנן לפי שנים.
- **כתבות**: טבלה של כל הכתבות מכל תוכני העניינים, עם סינון לפי שם ומדור.
- 🎲: עמוד אקראי.

## תוכן העניינים

תוכני העניינים של כל 126 הגליונות הוקלדו ידנית, בקבצים `toc/NNN.json`.
לגליון שאין לו קובץ כזה, תוכן העניינים מחולץ אוטומטית מה-OCR של עמוד 3
(התוצאה סבירה, אבל לא מושלמת).

כדי לתקן גליון עורכים את הקובץ `toc/NNN.json` שלו, ומריצים שוב את `run.sh`.
הריצה החוזרת לוקחת שניות, כי ה-OCR כבר שמור.
אחרי הריצה המלאה, כל עמודי תוכן העניינים נשמרים בתיקייה `toc_pages/`.

## עמודים כפולים הפוכים

בחלק מהסריקות שני החצאים של עמוד כפול הפוכים (למשל עמוד 22 בצד שמאל ו-23 בצד ימין).
כדי לתקן, מוסיפים לקובץ `toc/NNN.json` של הגליון שורה כמו:

    "swap": [22, 24, "30-40"],

(המספר הנמוך של כל עמוד כפול הפוך, או טווח) ומריצים שוב `run.sh`.
רק העמודים שהשתנו עוברים OCR מחדש.

## פרסום ב-Cloudflare Pages

1. פותחים חשבון חינמי ב-cloudflare.com.
2. מריצים את `./deploy.sh` (ב-Mac אפשר גם לגרור ל-Terminal את `deploy.command`).
   - בפעם הראשונה הסקריפט מתקין wrangler (וגם Node.js אם חסר או ישן מדי), ומדפיס קישור התחברות ל-Cloudflare:
     מעתיקים אותו לדפדפן שבו מחוברים ל-Cloudflare ומאשרים.
   - חלופה להתחברות: יוצרים ב-Cloudflare API Token עם ההרשאות Cloudflare Pages: Edit ו-D1: Edit,
     ומריצים: `CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=... ./deploy.sh`
   - הוא מרכיב את התיקייה `deploy` (האתר + קובצי ה-PDF, בלי לשכפל נפח בדיסק),
     בודק שכל קובץ קטן מ-25MB ושיש פחות מ-20,000 קבצים, ומעלה.
   - ההעלאה הראשונה של כ-3.7GB תיקח זמן. בהעלאות הבאות עולים רק קבצים שהשתנו.
3. כתובת האתר מודפסת בסוף, בדרך כלל https://wiz-archive.pages.dev.
   לשם פרויקט אחר: `./deploy.sh my-name`.

קובץ PDF שגדול מ-25MB לא יעלה. הסקריפט מציין אותו, ובאתר פשוט לא יופיע לו כפתור PDF.
אחרי כל שינוי (למשל תיקון תוכן עניינים): `run.sh` ואז `deploy.sh`.

## REST API

האתר המפורסם כולל API פתוח לחיפוש ולגישה לנתונים, עם תיעוד בכתובת `/developers`.
הוא רץ על Cloudflare Pages Functions (התיקייה `functions`) ומסד נתונים D1.
`deploy.sh` יוצר את מסד הנתונים בפעם הראשונה (ושומר את פרטיו ב-`wrangler.toml`),
ומעלה אליו רק גליונות שהשתנו (מאות כתיבות במקום ~30,000 בייבוא מלא).
בתוכנית החינמית: עד 100,000 בקשות API ביום, ועד 100,000 שורות שנכתבות למסד הנתונים ביום.
כשנדרש ייבוא מלא (בפעם הראשונה, או אחרי שינוי במבנה המסד), הסקריפט שואל לפני שהוא מבצע אותו.

## מבנה התיקייה

```
pdfs/        הסריקות המקוריות (לא משתנות)
toc/         תוכני עניינים מתוקנים (JSON)
site/        האתר: index.html + תמונות עמודים + אינדקס
work/        מטמון OCR (אפשר למחוק, אבל אז ה-OCR ירוץ מחדש)
build.py     הבנייה
run.sh       התקנה והרצה (run.command: עטיפה ללחיצה כפולה ב-Mac)
deploy.sh    פרסום ב-Cloudflare (deploy.command: עטיפה ב-Mac)
```

נפח משוער אחרי בנייה מלאה: כ-2GB בתיקייה `site/img` (תמונות העמודים לקורא), כ-100MB אינדקס
וכ-2GB בתיקייה `work` (מטמון. אפשר למחוק את `work/raw` בסוף).
