# ארכיון WIZ: אתר מקומי עם חיפוש

## הפעלה ראשונה (Mac)

1. מעתיקים את כל קובצי `wiz-001.pdf` עד `wiz-126.pdf` לתיקייה `pdfs`.
2. פותחים Terminal, גוררים לתוכו את הקובץ `run.command` ולוחצים Enter.
   (אפשר גם לחיצה כפולה על הקובץ. אם macOS חוסם אותו: קליק ימני ← Open.)
3. בפעם הראשונה הסקריפט מתקין את Homebrew, Tesseract (כולל עברית) ו-Poppler.
   ההתקנה לוקחת כמה דקות ועשויה לבקש את סיסמת המחשב.
4. אחר כך רץ ה-OCR. על 126 גליונות (כ-6,000 עמודים) זה ייקח בערך 30 עד 60 דקות,
   תלוי במחשב. אפשר לעצור באמצע (Ctrl+C) ולהריץ שוב. עמודים שכבר עובדו לא יעובדו מחדש.
5. בסוף האתר נפתח בדפדפן. בפעמים הבאות פשוט פותחים את `site/index.html`.
   לא צריך שרת ולא צריך אינטרנט.

## מה יש באתר

- **גליונות**: כל הכריכות, מסודרות לפי שנים.
- **דף גליון**: תוכן העניינים עם קישורים ישירים לעמודים, ותמונות מוקטנות של כל העמודים.
- **קורא**: עמוד בודד או כפול. מדפדפים בחיצים ←/→, לחיצה על העמוד מגדילה אותו.
  מילות החיפוש מסומנות בצהוב על גבי הסריקה, ובפאנל הצד מופיע הטקסט שזוהה.
- **חיפוש**: בכל הטקסט של כל הגליונות. חיפוש של כמה מילים מחזיר עמודים שבהם מופיעות כולן,
  ו-"ביטוי מדויק" נכתב במירכאות. אפשר לסנן לפי שנים.
- **כתבות**: טבלה של כל הכתבות מכל תוכני העניינים, עם סינון לפי שם ומדור.
- 🎲: עמוד אקראי.

## תוכן העניינים

לכל גליון שאין לו קובץ בתיקייה `toc/`, תוכן העניינים מחולץ אוטומטית מה-OCR של עמוד 3.
התוצאה סבירה, אבל לא מושלמת. גליונות 1, 10, 50, 80, 100 ו-126 כבר מוקלדים ידנית.

כדי לתקן גליון יוצרים קובץ `toc/NNN.json` באותו מבנה כמו הקבצים הקיימים, ומריצים שוב את `run.command`.
הריצה החוזרת לוקחת שניות, כי ה-OCR כבר שמור.
אחרי הריצה המלאה, כל עמודי תוכן העניינים נשמרים בתיקייה `toc_pages/`.

## ספרדים הפוכים

בחלק מהסריקות שני החצאים של עמוד כפול הפוכים (למשל עמוד 22 בצד שמאל ו-23 בצד ימין).
`run.command` יוצר את התיקייה `review` עם תמונה לכל גליון: השוליים התחתונים של כל עמוד כפול,
כפי שהוא מוצג באתר. בכל שורה המספר הגבוה צריך להיות משמאל והנמוך מימין.
כדי לתקן, מוסיפים לקובץ `toc/NNN.json` של הגליון שורה כמו:

    "swap": [22, 24, "30-40"],

(המספר הנמוך של כל עמוד כפול הפוך, או טווח) ומריצים שוב `run.command`.
רק העמודים שהשתנו עוברים OCR מחדש.

## פרסום ב-Cloudflare Pages

1. פותחים חשבון חינמי ב-cloudflare.com.
2. מריצים את `deploy.command` (גוררים ל-Terminal ולוחצים Enter).
   - בפעם הראשונה הסקריפט מתקין Node.js ו-wrangler, ומדפיס קישור התחברות ל-Cloudflare:
     מעתיקים אותו לדפדפן שבו מחוברים ל-Cloudflare ומאשרים.
   - חלופה להתחברות: יוצרים ב-Cloudflare API Token עם הרשאת Cloudflare Pages: Edit,
     ומריצים: `CLOUDFLARE_API_TOKEN=... CLOUDFLARE_ACCOUNT_ID=... ./deploy.command`
   - הוא מרכיב את התיקייה `deploy` (האתר + קובצי ה-PDF, בלי לשכפל נפח בדיסק),
     בודק שכל קובץ קטן מ-25MB ושיש פחות מ-20,000 קבצים, ומעלה.
   - ההעלאה הראשונה של כ-3.7GB תיקח זמן. בהעלאות הבאות עולים רק קבצים שהשתנו.
3. כתובת האתר מודפסת בסוף, בדרך כלל https://wiz-archive.pages.dev.
   לשם פרויקט אחר: `deploy.command my-name`.

קובץ PDF שגדול מ-25MB לא יעלה. הסקריפט מציין אותו, ובאתר פשוט לא יופיע לו כפתור PDF.
אחרי כל שינוי (למשל תיקון תוכן עניינים): `run.command` ואז `deploy.command`.

## REST API

האתר המפורסם כולל API פתוח לחיפוש ולגישה לנתונים, עם תיעוד בכתובת `/developers`.
הוא רץ על Cloudflare Pages Functions (התיקייה `functions`) ומסד נתונים D1.
`deploy.command` יוצר את מסד הנתונים בפעם הראשונה (ושומר את פרטיו ב-`wrangler.toml`),
ומעלה אליו רק גליונות שהשתנו (מאות כתיבות במקום ~30,000 בייבוא מלא).
בתוכנית החינמית: עד 100,000 בקשות API ביום, ועד 100,000 שורות שנכתבות למסד הנתונים ביום.
כשנדרש ייבוא מלא (בפעם הראשונה, או אחרי שינוי במבנה המסד), הסקריפט שואל לפני שהוא מבצע אותו.

## מבנה התיקייה

```
pdfs/        הסריקות המקוריות (לא משתנות)
toc/         תוכני עניינים מתוקנים (JSON)
site/        האתר: index.html + תמונות עמודים + אינדקס
work/        מטמון OCR (אפשר למחוק, אבל אז ה-OCR ירוץ מחדש)
build.py     הבנייה
run.command  התקנה והרצה
```

נפח משוער אחרי בנייה מלאה: כ-2GB בתיקייה `site/img` (תמונות העמודים לקורא), כ-100MB אינדקס
וכ-2GB בתיקייה `work` (מטמון. אפשר למחוק את `work/raw` בסוף).
